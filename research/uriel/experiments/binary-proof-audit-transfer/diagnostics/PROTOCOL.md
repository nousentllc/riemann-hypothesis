# Prospective audit of the observable packets

This is a deterministic design check on the pooled, single-copy, 24-record holdout. The audit uses only the two fixture generators, the public renderer and administration schema, and the finite state oracle. It reads no model outputs. This protocol was written before the combined shortcuts were calculated. During circuit construction we already knew the circuit stratum counts and the distribution 1,2,1 of useful menu positions; those are design checks rather than fresh predictions.

1. Check twins differ only in the initial evidence, that each truth/observation table is identical across twins, and that the same public text and menu/ID schema are delivered to both arms. Test invariance to hidden actual state, eligibility and truth/observation tables after keeping all public fields, state IDs and their order fixed. A one-line leakage finding is not a general security or semantic information-independence proof.
2. Calculate the strongest one-lookup target for each possible true state, and whether productive items split all possible observation cells into homogeneous truth classes. Tabulate pooled and domain-specific oracle coverage, including initial ambiguity, missing-opportunity loss under fixed lookup, and pairwise wins potential.
3. Give all fixed policies an oracle-quality reasoner and certificate writer after their action. Compare no lookup, each fixed displayed menu position, the best-prior-ambiguity and best-state-partition heuristics (using only compatible observations for the second heuristic), and fully informed optimal lookup. Show case and both-twins family results. Report constant Y/N/U and other surface verdict shortcuts separately as label-only outcomes.
4. In a prospective cross-family diagnostic, use the other five families per domain to predict one new family's labels from superficial fields only (evidence token, compatible-set size, menu vocabulary length, presentation order/lexical identifiers). Ties use a fixed lexicographic tie-break. These are descriptive sensitivity checks rather than inference on a held-out population. Also report the best in-sample lookup position by domain, if informative. Check whether selecting an actual truth from the first/last printed state, first compatible state, or a majority of compatible state truth values ever works as an initial/final answer under the oracle reporting rule. Do not credit an unsupported sign as certified.
5. Inspect whether domain and family designs reuse the same finite-candidate observation/filtering mechanism. Distinguish transfer across represented mathematical content from autonomous open-ended discovery or proof reconstruction.

Any design change after this diagnostic is a separate documented amendment. Existing held-out model responses, if any, are outside this audit.
