# One lookup and a supporting certificate

**Prospective design, 24 November 2026.** A general checklist and a procedure distilled from the earlier proof traces each have 125 whitespace-delimited words. Both receive the same instructions on the output format and the same finite set of possible cases. This tests the incremental value of the supplied procedure on a fixed model. The case authors work separately from the prompt author. Existing worked examples, including the parallel-branch illustration and binary mass calculation, are development material.

## Development and spend

Use the installed Qwen2.5 3B Q4_K_M first, with temperature zero, a common paired seed, 8,192-token context and up to 512 generated tokens per turn. The adapter contacts only the Ollama service on the loopback interface. The paid inference ceiling is $0. The first development variant of each of two families per domain, in both arms, gives eight sessions. Fix the variant order lexicographically within a family. If even one arm has no parseable final answers in a domain, or the two arms together earn zero certified development cases overall, use the installed gpt-oss 20B MXFP4 with low reasoning, the same context and up to 2,048 generated tokens, then repeat the development check. Repeat no model verdict to fish for a better answer. If both arms certify all development items, mark a ceiling concern and use the first model as scheduled. If the second model also fails the floor check, diagnose the instrument on development data before freezing the scored pilot. Record every attempted configuration. Compute format and time costs separately. Scope is a local, text-only session with one optional observation and no file-search tool.

## Study population and freeze

Use six proof families and six independent synthetic DC circuit layouts. Each has two related visible records with a single evidential change. Formal packets are finite, source-anchored tasks with explicit alternatives. Source provenance and any differences between the original theorem and a finite specialization are documented separately. No scored family can appear in development. No evaluation case may be solved by an example in the procedure. Prepare and verify the finite-state oracle offline, including at least one determinate yes and no, and examples in each domain already settled, resolvable by one lookup, and unresolved by all allowed lookups. List counts and check pair differences before the model sees a scored packet. File hashes cover the instruments, settings, schedules, prompts, key, generators and runner. Stop on any hash mismatch. Rerunning an interrupted experiment may resume only the same registered requests.

## Administration and scoring

12 families × 2 records × 2 arms = 48 fresh scored sessions. Use randomized run order from a frozen seed and no chat history between sessions. The first answer gives an initial verdict Y/N/U, a certificate of state IDs, and either one menu selection or NONE. If an item is requested, deliver only that actual observation, allow one final verdict and certificate, then stop. A determinate certificate lists exactly the compatible state IDs. An ambiguous certificate gives exactly two different compatible state IDs that disagree on the truth of the claim. Enumerating the finite packet universe and checking the claim on the returned IDs is an executable certificate of the answer. This format tests use of an explicit finite universe; it gives the agent substantial help compared with open-ended research.

The principal case target is the strongest verdict attainable for that record using at most one permitted observation. The oracle is allowed to calculate this ceiling from the true simulated record. Separately record whether any action can distinguish both truth classes in advance for all possible outcomes. Certify a case only if the agent attains the principal target and its final certificate checks against the evidence it actually saw. A complete family requires both variants. An unresolved verdict after a wasted lookup earns no case credit if an available lookup would have settled the record. A premature Y or N remains visible even if a later turn repairs it. Missing or invalid answers earn no success credit. Never count repeated translations or two arms of one family as independent tests.

Primary reporting uses the 12 family pairs (wins, ties, losses), per-domain net differences, exact two-sided conditional sign test on discordant families and conditional binomial 95% interval where defined. Report underlying case decisions, checked certificates, directed error (wrong sign versus unwarranted answers on ambiguous evidence), lookup utility, time and token counts. A session with no lookup makes only one assertion. Unsupported assertion counts include definitive statements inconsistent with the answer licensed at that point, and missing responses are reported separately.

Advance to a separately keyed retrieval replication if the method gains at least one net family in each domain, pooled unsupported assertions do not rise, and pooled certified determinate cases do not fall. The thresholds allocate research effort. No significance or broad transfer claim follows from passing them. A null at floor or ceiling is evidence about sensitivity of this panel. Document discrepancies before considering any revised experiment. Any later retrieval study must preserve independent task families.
