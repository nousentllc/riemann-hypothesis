# Source evidence

Run `python3 -B source_trace.py --source /path/to/extracted/pin --out results/source_trace.json` in this directory. The program reads the original commit's tracked Git tree and authenticates each cited Lean file from its bytes. Every original-source link in this directory's Markdown contributes an inclusive line span. Duplicate citations of the same span retain their document names and labels under one record. Each span digest includes the source line endings, including the last line's newline when present. [Manifest](results/source_trace.json)

Nine controls compare code at specified locations spanning pair-dependent exception construction, the common window, rescaling, application to the chosen host field, and the family index used in the final implication. For example, one mutation exchanges the ordered prime arguments when the proof asks for the window. A second applies the bound to an independent field while retaining the original identification proof. A third changes the index used for the final host's auxiliary hypotheses. Each control keeps the original expression as a comment on the mutated line. The check examines executable text after masking Lean comments and string literals. The tests operate on in-memory copies.

These controls establish the recorded spelling, argument order, and source locations at the pinned revision. Renaming a local variable or reformatting a checked application across source lines can also invalidate this lexical check. The proof term and Lean's type checker determine definitional equality, implicit arguments and logical dependence. The build evidence elsewhere in the suite records which of those stronger checks ran.
