# What remains after removing the served-orbit omission?

Let $B$ be the sum, over the finite prime set `PR`, of `log(p)/p` times the number of retained points marked bad at $p$. Let $m=|J|$, $T=|TT|$, $U=Tmb$, and $g=100Kx^{4\varepsilon}/x$. The imported source defines these quantities and the loss being bounded. The supplement imports the source definitions directly.

## Results and scope

1. **Zero omission.** The original coverage condition says that every missing retained point for a served prime belongs to its bad set, and that prime belongs to `PR`. With $m,a\ge0$, the served omission sum lies between zero and $4amB$. If $B=0$, that sum equals zero. The proof needs no assumption that an arbitrary natural number in `PR` has positive logarithmic weight.
2. **Ten surviving budgets.** Under `Windows`, `LargeX`, $m\ge0$, and $T\ge1$, the ten other entries of the original eleven-entry discriminant ledger sum to at most $(2\log(4)C+12g)U$. The upper-prime entry consumes three units of $gU$, and each of its nine companions consumes one. The omitted entry had been allocated one additional unit in the coarser sum. This arithmetic does not assert saturation.
3. **Partial bad mass.** Under the original prime-class hypotheses, the actual difference `ASK − Ga` is bounded by $(2\log(4)C+12g)U+4amB$, pointwise in each index of the original loss data. The numerical value of $B$ can be inserted when supplied. The proof takes the same choices of $P,D,J,TT,PR,\mathrm{BAD}$ through the original gain, first-prime, second-prime and coverage estimates. It assumes the same window conditions and the existence of one shared first-order cutoff constant in the same quantifier order as the source. The independent prime-log sum for `io` is a separate output of the original proof.
4. **Zero bad mass.** Setting $B=0$ in the partial-mass bound gives $(2\log(4)C+12g)U$. This is conditional on the stated data satisfying the original loss hypotheses and on their weighted mass being zero. Moving retained points may also change the gain data or the other hypotheses. We do not construct two arithmetic witnesses holding those quantities fixed.
5. **Exact scale of the deleted cap.** The source's preallocated cap is exactly $4x^{-1+\varepsilon}U$ for $x>0$, including zero $m$ and zero $T$. Its coarser allowance is $gU$. One is a budget constructed from the source's permitted size of $B$. The other is a later ceiling on that budget. Neither gives a measured decrease in the loss.
6. **Surviving leading component.** The source's named `SizePrHighLower` states $2\log(4)C\,U\le t_{\rm PrHigh}$. The supplement proves it directly from the five-term expansion of $X'Q_2$. Its first term is $Cb$. The other four are nonnegative under the window hypotheses. A fixed positive $C$ and positive $U$ therefore leave an order-$U$ floor in this *budget component* even when $B=0$. This gives no lower bound on `ASK − Ga`. The restriction $C>0$ matters for the normalized floor to be positive.

## Reproduce the Lean check

Prepare the checkout, pinned original source, compiler and compiled Mathlib packages described in the [public retained-host replay instructions](https://github.com/nousentllc/riemann-hypothesis/blob/9ac7e1b546b132edde02709e1c0af1bfccd40755/research/uriel/experiments/retained-host/REPRODUCE.md). The project-specific objects used by earlier experiments are unnecessary for this supplement. Supply a work directory that does not yet exist.

```sh
python3 -B replay.py --checkout "$CHECKOUT" --original "$ORIGINAL" \
  --toolchain "$LEAN_ROOT" --mathlib "$MATHLIB" --work "$NEW_WORK" \
  > verification-local.json
```

The script checks the compiler revision and the package revisions recorded by the original Lake manifest. It matches each source against the original pinned Git blob, compiles all 36 project modules in the direct import's closure from those sources, compiles this supplement, checks the printed axioms, and invokes the separate kernel checker on the original discriminant module and the supplement. The verification record contains the exact package revisions, individual project object hashes and kernel output. It relies on the installed Lean toolchain and compiled Mathlib package objects. It does not replay every Mathlib dependency or the full RH endpoint.
